# The Sims Bowling — native recompilation and decompilation

A port of Electronic Arts' iPod click-wheel game *The Sims Bowling* (`SimsBowling_1_1_3002478.bin`,
2007) to modern machines, the fourth title after *Mini Golf*, *Lost* and *Texas Hold'em*. The
game is first **statically recompiled** — every ARM function becomes a C++ function that runs
the same instructions on a small CPU-state struct — so it runs natively from day one. Functions
are then **hand-decompiled** one at a time into real, named, readable C++, each swap proven
against the recompiled version. The iPod's application frameworks (OpenGL ES, audio, file I/O,
click wheel) are reimplemented as a host library, `libeapp`, behind plain C++ interfaces
(`src/framework/`), and the parts of all that which belong to no single title are compiled from
`../common` rather than copied here.

`PLAN.md` is the plan of record: what this game is, what it takes from the other three titles
and how, where it differs from them, and a progress log of what has been established. The
code-quality rules that bind every recomp are in `../Mini Golf/PLAN.md` § "Code quality"; read
them before contributing.

## Layout

```
PLAN.md                  the plan of record, with the schedule and the progress log
README.md                this file
CMakeLists.txt           build; targets `bowling` (SDL3) and `bowling-headless` (tests)
tools/
  survey.py              what is in the image — every number PLAN.md states
  funcs.py               seed the function table gen/funcs.json (vectors, live edges, pointers)
  emit.py                run the shared ARM → C++ recompiler (../common/tools/recomp) into gen/
  progress.py            how much of the game is still recompiled rather than decompiled
  manifest.py            the game folder's file table -> src/gamedata/manifest_data.cpp
  port-from-holdem.py    copy what is not yet shared from ../HoldEm, and record it
  oracle-emulator/       a pinned copy of the emulator; recordings are made with this one
gen/                     GENERATED by emit.py, never hand-edited (gitignored)
src/
  runtime/               the eApp image, the frame pump (main.cpp), region sizes (memory.cpp);
                         cpu.h / runtime.h / memory.h forward to the shared core
  framework/             what the game may ask the platform to do — graphics (shared), audio,
                         storage, controls, device, music library. Plain C++, no ordinals
  libeapp/               the iPod frameworks on the host: files (async_file.cpp), audio, input,
                         misc, metadata; arm_abi.cpp adapts them to the ARM calling convention
                         for the recompiled code; imports.json is this title's ordinal table
  gamedata/              this title's file manifest; the zip reader is shared, the installer here
  game/                  hand-decompiled game code; grows as gen/ shrinks (empty so far)
  platform/sdl3/         window, audio, keyboard, the macOS settings window (desktop)
  platform/null/         no I/O (headless test runs)
tests/
  scripts/*.script       scripted input, the same FRAME: ACTION format the emulator reads
  expected/*.calls       framework-call logs recorded from the pinned emulator — the oracle
  exact-allow.txt        the one ordinal the exact comparison drops, and why
  unit/                  stand-alone unit tests of the runtime and platform code
  record.sh              record a case from the pinned emulator (the flags are part of the case)
  diff.sh                run a case headless and compare its call log with the recording
  frames.sh              the picture oracle: screenshots from both sides, compared
  game-dir.sh            where the game's files are; a fresh private copy per run, save removed
analysis/                the reverse-engineering evidence for this title (README.md there)
reference/               MANIFEST.md (the pinned emulator) and PORTED.md (the copies)
```

## Building

Requirements: CMake ≥ 3.21, a C++17 compiler, Python 3.10+, SDL3 (via `pkg-config` or its
CMake package), zlib, Rust (for the pinned emulator), and the game's folder — `1500C`, 63
files, ~53 MB — which is not included: it is the owner's game data.

```sh
python3 tools/funcs.py && python3 tools/emit.py      # gen/ — the recompiled game
cmake -B build && cmake --build build
./build/bowling                                      # asks for the game's folder the first time
./build/bowling --gamedir="…/Games_RO/1500C"         # or run straight from it, unchecked
```

Release (`-O3 -g`, assertions kept) is the default and matters: the renderer is a software
rasteriser. `-DCMAKE_BUILD_TYPE=RelWithDebInfo` is `-O1 -g`, for stepping recompiled code next
to the emulator. `-DBOWLING_SANITIZE=ON` builds with ASan/UBSan.

The game's files are installed to the per-user data directory on first launch (macOS
`~/Library/Application Support/iPod The Sims Bowling/1500C`; `BOWLING_DATA_DIR` overrides) and
verified against `src/gamedata/manifest_data.cpp` on every launch. `--install=PATH` installs
from a folder or zip without the dialog. The game keeps its save in `savefile.dat` at the root
of its folder, which the manifest ignores.

## Testing

```sh
cargo build --release --manifest-path tools/oracle-emulator/Cargo.toml \
    --target-dir build/oracle-emulator                # the pinned emulator, once
ctest --test-dir build                               # unit tests, oracles, pictures
tests/record.sh <case>                               # (re)record tests/expected/<case>.calls
tests/diff.sh <case> build/bowling-headless [--exact] # one case, by hand
```

Every recorded case runs three ways: `oracle_<case>` compares the framework-call sequence on
the arguments each ordinal takes; `exact_<case>` compares every logged word, which only
register-for-register code can pass and is what the pure recompilation is; `frames_<case>`
(for a script with a `shot`) compares the screenshot with the emulator's at a threshold. A case
that needs the game's folder skips (exit 2) when it is not there. `tests/game-dir.sh` gives every
run a fresh copy of the folder with the save removed, because the game writes into it.

Recordings come from the **pinned** emulator under `tools/oracle-emulator/` (see
`reference/MANIFEST.md`), never the live tree, and `tests/record.sh` spells out the flags a case
is made with — they are part of the case. The recomp side runs with `--emulator-firmware`, which
reproduces the two things the emulator does that a real run should not: it refuses the game's
file writes (the emulator's default, and what the recordings depend on) and answers the store
calls "not ready". The exact comparison drops one ordinal from both logs — the host's wall
clock, which the emulator answers with the real date and time of the recording — and
`tests/exact-allow.txt` says so.

## Playing

Up/Down scroll a menu one row (hold to keep scrolling), Left/Right are the wheel's two buttons,
Space is the centre button — hold it where the game says to — Tab is Play/Pause and Escape is
Menu, which pauses a game. `,`/`.` and `[`/`]` do what they did in the other titles; Settings >
Input rebinds any of it. Save & Exit in the Pause menu writes the save and ends the program, the
way it handed the iPod back to its own menu.

## Debugging aids

`--call-log=FILE` (or `-`) writes the framework-call log; `--frames=N` stops after N frames;
`--time=HH:MM` fixes the clock; `--trace-entry=ADDR,...` prints the registers at every entry to
a recompiled function (pairs with the emulator's `play --watch-pc`); `--dump-entry=` and
`--dump-frame=` print guest memory at an entry or after every frame; `--trace-from=FRAME` keeps
the entry trace quiet until that frame, so every function can be traced for one frame (that is
how both recompiler bugs in the progress log were found). `BOWLING_TRACE_FILES=1` prints one line
per file operation (the emulator's `--file-ops=N` is the other side). `BOWLING_WATCH=ADDR` stops
with a backtrace at the first store to a guest word while the entry trace is on,
`BOWLING_WATCH_VALUE=V` narrows it to one value, and `BOWLING_WATCH_LOG=1` turns it into a running
log instead — the counterpart of the emulator's `--watch-mem=ADDR`. `BOWLING_TRACE_UNMAPPED=1`
prints, with a host backtrace, every guest access outside mapped memory — this game makes a
few, and they are answered as the emulator answers them (`src/runtime/memory.cpp`).

## Status

2026-08-28: the pure recompilation (2 402 functions, 71 924 instructions) runs natively, and all
five recorded cases — a 600-frame boot, the Main Menu, two Selects to the Controls screen, a
full first throw (Bowl Now!, Set position, Aim, Set power, the ball rolled), and the Volume row —
are identical to the emulator call for call and word for word; every screenshot along the way is
the emulator's, pixel for pixel. `ctest`: 22/22. Getting there took three changes to the shared
recompiler, `glDrawElements` in the shared rasteriser, and a resize that keeps the picture, each
verified against the other three titles first. Nothing is hand-decompiled yet. `PLAN.md`
§ "Progress log" has the detail, and what is *not* yet established.
