# Cubis 2 — native recompilation and decompilation

A port of the iPod click-wheel edition of *Cubis 2* (`Cubis2_1_1_2563292.bin`, 2007 — cubes
fired into an isometric grid, matched three at a time) to modern machines, the sixth title after
*Mini Golf*, *Lost*, *Texas Hold'em*, *The Sims Bowling* and *Vortex*. The game is first
**statically recompiled** — every ARM function becomes a C++ function that runs the same
instructions on a small CPU-state struct — so it runs natively from day one. Functions are then
**hand-decompiled** one at a time into real, named, readable C++, each swap proven against the
recompiled version. The iPod's application frameworks (OpenGL ES, audio, file I/O, click wheel)
are reimplemented as a host library, `libeapp`, behind plain C++ interfaces (`src/framework/`),
and the parts of all that which belong to no single title are compiled from `../common` rather
than copied here.

`PLAN.md` is the plan of record: what this game is, what it takes from the other five titles and
how, where it differs from them, and a progress log of what has been established. The
code-quality rules that bind every recomp are in `../Mini Golf/PLAN.md` § "Code quality"; read
them before contributing.

**One thing this title changed outside its own folder.** The emulator drew every cube on this
game's board grey, because it ignores the GL constant colour register by default and the cubes
are grey `GL_LUMINANCE_ALPHA` sheets tinted through it. The fix — apply the register to a texture
that has no colour of its own, which is the rule the emulator already applied one format short —
is in the emulator tree and in `../common/src/ipod/libeapp/gles.cpp`, and it is verified against
all twenty titles in `Games_RO/` before this tree used it. `PLAN.md` difference 6 and
`reference/MANIFEST.md` are the record.

## Layout

```
PLAN.md                  the plan of record, with the schedule and the progress log
README.md                this file
CMakeLists.txt           build; targets `cubis` (SDL3) and `cubis-headless` (tests)
tools/
  survey.py              what is in the image — every number PLAN.md states
  funcs.py               seed the function table gen/funcs.json (vectors, live edges, pointers)
  emit.py                run the shared ARM → C++ recompiler (../common/tools/recomp) into gen/
  progress.py            how much of the game is still recompiled rather than decompiled
  manifest.py            the game folder's file table -> src/gamedata/manifest_data.cpp
  assets.py              every shipped image identified from its own header, and every texture
                         the game uploads joined against those files — no emulator involved
  probe.sh               run a script through the pinned emulator and keep what it produced
  port-from-vortex.py    copy what is not yet shared from ../Vortex, and record it
  oracle-emulator/       a pinned copy of the emulator; recordings are made with this one
gen/                     GENERATED by emit.py, never hand-edited (gitignored)
src/
  runtime/               the eApp image, the frame pump (main.cpp), region sizes (memory.cpp);
                         cpu.h / runtime.h / memory.h forward to the shared core
  framework/             what the game may ask the platform to do — graphics (shared), audio,
                         storage, controls, device, music library. Plain C++, no ordinals
  libeapp/               the iPod frameworks on the host: files (async_file.cpp), audio, input,
                         misc, metadata; arm_abi.cpp adapts them to the ARM calling convention
                         for the recompiled code; imports.json is this title's ordinal table
  gamedata/              this title's file manifest; the zip reader is shared, the installer here
  game/                  hand-decompiled game code; grows as gen/ shrinks (empty so far)
  platform/sdl3/         window, audio, keyboard, the macOS settings window (desktop)
  platform/null/         no I/O (headless test runs)
tests/
  scripts/*.script       scripted input, the same FRAME: ACTION format the emulator reads
  expected/*.calls       framework-call logs recorded from the pinned emulator — the oracle
  unit/                  stand-alone unit tests of the runtime and platform code
  record.sh              record a case from the pinned emulator (the flags are part of the case)
  diff.sh                run a case headless and compare its call log with the recording
  frames.sh              the picture oracle: screenshots from both sides, compared
  game-dir.sh            where the game's files are; a fresh private copy per run, writes removed
analysis/                the reverse-engineering evidence for this title (README.md there)
reference/               MANIFEST.md (the pinned emulator) and PORTED.md (the copies)
```

## Building

Requirements: CMake ≥ 3.21, a C++17 compiler, Python 3.10+, SDL3 (via `pkg-config` or its CMake
package), zlib, Rust (for the pinned emulator), and the game's folder — `99999`, 118 files,
~10 MB — which is not included: it is the owner's game data.

```sh
python3 tools/funcs.py && python3 tools/emit.py      # gen/ — the recompiled game
cmake -B build && cmake --build build
./build/cubis                                        # asks for the game's folder the first time
./build/cubis --gamedir="…/Games_RO/99999"           # or run straight from it, unchecked
```

Release (`-O3 -g`, assertions kept) is the default and matters: the renderer is a software
rasteriser. `-DCMAKE_BUILD_TYPE=RelWithDebInfo` is `-O1 -g`, for stepping recompiled code next
to the emulator. `-DCUBIS_SANITIZE=ON` builds with ASan/UBSan.

The game's files are installed to the per-user data directory on first launch (macOS
`~/Library/Application Support/iPod Cubis 2/99999`; `CUBIS_DATA_DIR` overrides) and verified
against `src/gamedata/manifest_data.cpp` on every launch. `--install=PATH` installs from a folder
or zip without the dialog. The game writes two files of its own into its folder —
`cubisgame.dat` and `cubissave.dat` — which the manifest ignores; the game's own `Manifest.plist`
names neither, which is how they were identified (PLAN.md difference 3).

## Testing

```sh
cargo build --release --manifest-path tools/oracle-emulator/Cargo.toml \
    --target-dir build/oracle-emulator                # the pinned emulator, once
ctest --test-dir build                               # unit tests, oracles, pictures
tests/record.sh <case>                               # (re)record tests/expected/<case>.calls
tests/diff.sh <case> build/cubis-headless [--exact]  # one case, by hand
tools/probe.sh <name> [play flags]                   # an exploratory emulator run, kept in analysis/
```

Every recorded case runs three ways: `oracle_<case>` compares the framework-call sequence on the
arguments each ordinal takes; `exact_<case>` compares every logged word, which only
register-for-register code can pass and is what the pure recompilation is; `frames_<case>` (for a
script with a `shot`) compares the screenshot with the emulator's at a threshold. A case that
needs the game's folder skips (exit 2) when it is not there. `tests/game-dir.sh` gives every run a
fresh copy of the folder with the game's own files removed, because the game writes into it.

Recordings come from the **pinned** emulator under `tools/oracle-emulator/` (see
`reference/MANIFEST.md`), never the live tree, and `tests/record.sh` spells out the flags a case
is made with — they are part of the case. The recomp side runs with `--emulator-firmware`, which
reproduces what the emulator does that a real run should not: the microsecond clock steps a fixed
amount per *call* rather than per frame, file writes are refused, and the store answers "not
ready".

**The emulator opens a window, and a click on it is a Select.** It also writes every screenshot
to `/tmp/ipod-shot-NN.png`, a path every title's picture oracle shares. `record.sh` refuses a
recording whose emulator output shows a press the script did not make, and `frames.sh` and
`probe.sh` copy each screenshot the moment the emulator announces it. Do not run two titles'
picture oracles at once (PLAN.md rule 11) — this project watched that rule produce a wrong answer
about twenty titles at once, and `build/sweep/run2.sh` is what it takes to be safe.

## Debugging aids

`--call-log=FILE` (or `-`) writes the framework-call log; `--frames=N` stops after N frames;
`--time=HH:MM` fixes the clock, which this game draws in its status bar; `--trace-entry=ADDR,...`
prints the registers at every entry to a recompiled function (pairs with the emulator's
`play --watch-pc`); `--dump-entry=` and `--dump-frame=` print guest memory at an entry or after
every frame; `--trace-from=FRAME` keeps the entry trace quiet until that frame, so every function
can be traced for one frame. `CUBIS_TRACE_FILES=1` prints one line per file operation (the
emulator's `--file-ops=N` is the other side). `CUBIS_WATCH=ADDR` stops with a backtrace at the
first store to a guest word while the entry trace is on, `CUBIS_WATCH_VALUE=V` narrows it to one
value, and `CUBIS_WATCH_LOG=1` turns it into a running log instead — the counterpart of the
emulator's `--watch-mem=ADDR`. `CUBIS_TRACE_UNMAPPED=1` prints, with a host backtrace, every
guest access outside mapped memory, which is answered as the emulator answers it
(`src/runtime/memory.cpp`). `IPOD_TEX_LOG=1` prints one line per texture upload, which pairs with
the emulator's `EAPP_TEX_FMT_LOG=1` and is how a texture that decodes differently on the two
sides is found.

## Status

2026-08-28: the pure recompilation (1 382 functions, 64 827 instructions) runs natively, and all
four recorded cases — a 600-frame boot, the main menu, one Select to Name Entry, and a name
entered, NEW GAME and the first level played to GAME STATS — are identical to the emulator call
for call and word for word, in semantic and exact form, on the first attempt. Every native picture
along the way is the emulator's, pixel for pixel, including the board of coloured cubes.
`ctest --test-dir build` is 19 of 19 and `build/cubis` builds.

Getting there needed no change to the shared recompiler and two to the shared *rasteriser*, both
of which were defects in every title rather than in this one: the GL constant colour register now
reaches a texture that has no colour of its own (without it this game's whole board rendered
grey), and a 1:1 blit's half-texel tie is now decided with a tolerance instead of by the last bit
of a float (without it a full-screen backdrop rendered as noise — Tetris, PAC-MAN and Mahjong were
affected too). Both were verified against all twenty titles in `Games_RO/` and all five other
recomps' suites before they were used here. Nothing is hand-decompiled yet.

`PLAN.md` § "Progress log" has the detail, and what is *not* yet established.
